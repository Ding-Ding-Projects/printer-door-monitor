Printer Door Monitor

Know when the printer door opens, and hear it too.

A small web app for your Docker host that watches the doors of a Bambu Lab printer, logs every opening and closing, and can ring a chime on the printer's own buzzer. It keeps watching with every computer closed.

Download the setup wizard Source

Every door

Front door, top cover, left and right doors, each shown open or closed as soon as the printer reports it.

A door log

Every opening and closing with the time, how long the door stayed open, and what the chime did. Search it, with regular expressions if you like.

Door chimes

Seven chimes for opening and seven for closing, from a classic ding-dong to the Westminster phrases. Preview them on the printer. They wait while it prints.

Runs anywhere with Docker

One image for x86-64 and ARM64. Install it with a GUI wizard, a double-click on host.bat, or Docker Compose.

Try the door log

This demo runs in your browser only. Click a door to open or close it and watch the log, the way the monitor records a real printer.

Install

All three ways use the published image ghcr.io/ding-ding-projects/printer-door-monitor and the same compose.yaml. Settings and the door log live in the door-monitor-data volume and survive updates.

With the setup wizard

  1. Download PrinterDoorMonitorSetup-<version>.exe from the latest release. It is one portable file; nothing else to install.
  2. Choose A Docker host over SSH (an SSH target such as docker@my-docker-host, using your SSH key) or This computer, and press Check Docker.
  3. Pick the port (8790 by default) and the version, then Install. The wizard pulls the image, starts it, waits for the health check and opens the page from your computer.
  4. Open the address it shows and finish the first-run setup.

With host.bat

Double-click host.bat for a menu, or use the options:

host.bat --detached
host.bat --logs
host.bat --detached --remote docker@my-docker-host
host.bat --stop --remote docker@my-docker-host
host.bat --detached --port 8791 --tag 1.0.0

--logs shows the status and the logs: F pauses or resumes, S switches the service, R refreshes, Q leaves and keeps the monitor running.

With Docker Compose

docker compose pull
docker compose up -d

Set DOOR_MONITOR_PORT and DOOR_MONITOR_TAG to change the port and the version.

First run

  1. Password. The first visitor chooses the password for the page.
  2. Printer. Enter the printer's IP address, serial number and LAN access code from its screen. The monitor connects at once and shows whether it worked. The access code stays on the server and is never shown again.
  3. Chimes. Turn the chime on, pick the opening and closing chimes, try them with Preview, and choose which doors ring. You can skip this.

The page

  • Doors: each door open, closed or not reported, with the print state and the time of the last report.
  • Door chime: the switch, both chimes with Preview, and the doors that ring.
  • Settings: language (English, Cantonese or both), theme, and the printer connection.
  • Door log: newest first, with a search box and a regular expression switch.

How it works

The monitor connects to the printer's MQTT service on port 8883 with TLS, as user bblp with the LAN access code, subscribes to device/<serial>/report and asks for a full report.

It reads the doors from bits 23 to 26 of print.stat (front door, top cover, left door, right door), falls back to bit 23 of print.home_flag for the front door, and reads door detection support from bit 12 of print.fun. This is the decoding Bambu Studio uses; the printer maker does not document it. The first reading after connecting only records the state, so a door that is already open is not an opening.

A chime is a gcode_line command: M17, M400 S1, one M1006 line per note on all three buzzer voices, M1006 W, M18. It turns the motors on and releases them, so it is never sent while the printer is running, paused, preparing or slicing.

The page is protected by a password (scrypt hash) and a signed session cookie. The settings, the password hash and the door log are files in the data volume.

Troubleshooting

Connection problem with the right details

Some printer firmware only accepts LAN connections from other software in LAN-only mode or with developer mode on. Check that setting on the printer screen, then press Save and connect again.

Doors show "Not reported"

The printer has not sent a door reading yet, or it has no door detection. The page says so when the printer reports no door detection.

The chime did not play

Look at the log: "waited, printing" means the printer was busy; "printer not connected" means the link was down. Preview tells you the same at once.

The page does not open from another computer

Check the firewall on the Docker host and that the port is free. host.bat --logs shows what the monitor is doing.
